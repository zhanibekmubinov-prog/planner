## MCP-коннектор (для следующей сессии)
- Схема как в CIS Platform (`app/blueprints/mcp` там ↔ `routers/mcp_oauth.py` + `routers/mcp.py` здесь). Claude регистрируется сам (`/oauth/register`), `/oauth/authorize` создаёт `McpPendingAuth` и уводит в Entra со state `mcp:<key>`; `/api/auth/callback` при таком state записывает `user_id` в pending и редиректит на `/oauth/consent?k=`; «Разрешить» → `McpAuthCode` → `/oauth/token` (PKCE) → `McpToken` (хеши). Refresh ротируется, старая пара отзывается.
- Новых настроек в Entra не нужно (redirect тот же). `PUBLIC_URL` нужен только если за прокси не приходит `X-Forwarded-Proto`.
- Инструменты — `mcp_tools.TOOLS` (name, description, inputSchema, handler). Добавить инструмент = функция `t_<имя>(db, user, args)` + запись в `TOOLS`. Ошибки — `ToolError` (текст уходит Claude как `isError`). Сущности резолвятся `_match()` по id/названию/части/словам. Записи через Claude помечены в `activity_log` `{"via": "mcp"}`.
- Права: владелец задачи — всё; исполнитель — `set_task_status` и `update_delegation` (status/report) по своим поручениям; `list_tasks scope=assigned_to_me` — «мне поручено».
- Удаления нет намеренно (решение владельца). Майндмапы через MCP пока не выведены.
- Проверка: `python test_mcp.py` из `backend/` (sqlite, без сети).

## Многопользовательский режим (для следующей сессии)
- Служебный `X-API-Token` = владелец (`OWNER_EMAIL`); Swagger работает как раньше. Пользовательские сессии — JWT HS256 (`SESSION_SECRET`, 30 дней) в `localStorage['planner.session']`; 401 → фронт показывает экран входа.
- `Person` — общий справочник; при входе пользователя запись `Person` с его почтой связывается (`user_id`) или создаётся. Удалять людей с `user_id` нельзя.
- Задачи: владелец правит всё; исполнитель — только `POST /tasks/{id}/status` и `PUT /delegations/{id}/report`. Фронт делит задачи на `store.tasks` (мои) и `store.inbox` (поручены мне другими).
- Каналы: Telegram — `User.telegram_chat_id` (админ без него получает глобальный `TELEGRAM_CHAT_ID`), почта — `User.email`; календарь — в ящик владельца задачи. Сводка `Digest` логируется с `entity_id = user.id`.
- Уведомление «Вам поручено» уходит исполнителю один раз (`assigned_notified_at`); существующие поручения помечены миграцией, чтобы не рассылать задним числом.

## Как устроены напоминания (для следующей сессии)
- Формула health-score живёт в двух местах: `frontend/src/Overview.tsx` (`buildReport`) и `backend/app/digest.py` (`build_report`). Менять — синхронно.
- Поручения: `Delegation.notified_at IS NULL AND check_at <= now AND status=open` → сообщение владельцу (Telegram, иначе email) → `notified_at`. Лог `Delegation/check_reminder`.
- Сводка: `digest_due()` — время ≥ `DIGEST_TIME` по `APP_TIMEZONE` и сегодня ещё не было `Digest/sent`. Ручная отправка пишется как `sent_manual` и на ежедневную не влияет.
- `Reminder.recipient`: `owner` — владельцу задачи (как раньше); `assignees` — всем людям с открытым поручением по задаче (Telegram: `person.user.telegram_chat_id` или `person.telegram_chat_id`; почта/календарь: `person.user.email` или `person.email`; событие в календаре исполнителя создаётся заново, id не хранится); `both` — и то и другое, исполнитель-владелец не дублируется. Ключи результата для исполнителей — `канал/Имя`.
- `Reminder.sent_at IS NULL AND fire_at <= now` → `deliver()` по каждому каналу из `channels`; при хотя бы одном успехе ставится `sent_at`; если не удаётся >24 ч — помечается `gave_up`. Результаты — в `activity_log` (`Reminder` / `sent|failed|gave_up`, payload = {канал: ok|ошибка}).
- `outlook_calendar`: событие 30 мин на время напоминания, id пишется в `Task.outlook_event_id`, повтор — PATCH.
- Сообщение содержит ссылку `FRONTEND_URL/?task=ID`; фронт по этому параметру открывает карточку.
- Токен Graph кэшируется в памяти процесса.

## Ответы владельцу про адресатов (2026-09-03)
- Поручение самому себе не появляется в «Мне поручено» — раздел только для задач, где владелец — другой человек (`store.inbox`). Уведомление «Вам поручено» самому себе тоже не шлётся.
- «Пора проверить у X» — всегда владельцу задачи. Уведомление исполнителю о поручении — одно, в течение минуты, Telegram (chat id) иначе почта.
