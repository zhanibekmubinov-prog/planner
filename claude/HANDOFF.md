## Что сделано в v1.6 (сессия 20)
- **Корзина (главная починка).** `soft_delete_project` забирает живые задачи проекта, `soft_delete_direction` — свои проекты с их задачами и задачи направления, **кроме** тех, что числятся ещё в одном живом направлении. `restore_*` возвращают задачи с тем же `deleted_at`, `hard_delete_*` стирают их вместе с контейнером. Задача, удалённая отдельно и раньше, за контейнером не возвращается — различаем по timestamp. Симптом «задачи удалённого проекта висят во „Все задачи“ как без проекта» закрыт тестами `test_v08_softdelete.py` и `test_ok_project_delete_takes_its_tasks_to_trash`.
- **Ручной порядок.** `Project.sort_order` / `Task.sort_order` (миграция `f2b6c7d8e9a0`, `server_default='0'`), `POST /projects/reorder`, `POST /tasks/reorder` (`schemas.ReorderIn`); недоступные id молча пропускаются.
- **Ответственные в задаче.** `TaskOut.assignees` (`schemas.TaskAssignee`) — из поручений, открытые впереди, на человека одна строка; `visible_tasks_query` грузит поручения через `selectinload`.
- **Панель.** У проекта своя стрелка → открытые задачи (до 10, дальше «ещё N»), состояние в `localStorage['planner.projects.expanded']`. Новый пункт **Action Tracker**.
- **Перетаскивание** (`src/dnd.ts`, общий код для панели и карты проектов): задача → проект / направление / другая задача; проект → другой проект (порядок) / другое направление (открывается окно «Перенос» с выбором «перенести/скопировать»).
- **Action Tracker** (`src/ActionTracker.tsx`): направление → проект → задачи, колонки «Задача · Ответственный · Срок · Статус · План действий», правка прямо в строке, фильтры, «Скопировать» и «Excel…» (CSV с BOM и `;`).

## Что где лежит (для следующей сессии)
- **Перетаскивание** — `frontend/src/dnd.ts`: типы переноса `text/task-id` / `text/project-id`, `insertBefore`, `siblingTasks`, `moveTaskToProject`, `reorderTasks`, `reorderProjects`, `dropTaskOnTask`, `dropProjectOnProject`. Панель и карта проектов вызывают только эти функции — правила переноса менять там, а не в компонентах. В `DirectionPage` карточка проекта ловит перенос проекта через `*Capture`-обработчики: обычные уже заняты переносом задач в `DropCard`.
- **Action Tracker** — `frontend/src/ActionTracker.tsx`. `buildGroups(store, filters)` собирает направление → проект → задачи (экспортируется, покрыт тестами), `tableRows(groups)` даёт плоскую таблицу для буфера и CSV. Ответственный берётся из `task.assignees` — отдельных запросов нет. Правка статуса у исполнителя идёт через `/tasks/{id}/status`, у остальных — обычным `PUT /tasks/{id}` (с `updated_at`, конфликт 409 обрабатывается как везде).
- **Корзина** — `backend/app/trash.py`. Ключ ко всему — `deleted_at`: одно действие пользователя = один timestamp, по нему же идёт восстановление и удаление навсегда. Меняя правила, менять и тексты подтверждений в `frontend/src/deletion.tsx` и счётчик «внутри N задач» в `Trash.tsx`.
- **Порядок** — `sort_order`. Ноль у всех = прежний порядок; на карте проектов ручной порядок включается только если хоть у одного проекта направления он больше нуля (`manualOrder` в `DirectionPage`).
- **Тесты.** Бэкенд: `backend/tests/` (sqlite во временной папке, схема пересоздаётся перед каждым тестом), запуск `python -m pytest tests -q`; отдельно `python test_mcp.py` и `python test_v06.py` (оба печатают `ALL OK`). Фронт: `frontend/src/__tests__/`, `npm test`; фикстуры стора — `fixtures.ts` (при добавлении поля в `Store` его надо добавить и туда).
- **Стенд для скриншотов:** `cd backend && python _serve_ui.py 8765` (sqlite с демо-данными + `frontend/dist`), в выводе — JWT владельца; дальше Playwright. Перетаскивание в Playwright проверяется вручную собранным `DragEvent` с `DataTransfer` (обычный `drag_to` для HTML5-переноса не работает).

## Правила работы в папке владельца (Cowork)
- Файлы записывать через мост, но **git не запускать вообще** (даже `git status` оставляет `.git/index.lock`, который потом блокирует коммит владельца). Если появился — `Remove-Item .git\index.lock`.
- Тесты гонять на копии в `$HOME`, не в папке владельца. Фронт в Linux-среде: копия `frontend` без `node_modules` → `npm ci` → сборка.
- Связь с компьютером может пропасть посреди сессии (сессии 18 и 20): готовые файлы держать в `/mnt/user-data/outputs/` и отдавать архивом в чат.
