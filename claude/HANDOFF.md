2. **`Access-Control-Max-Age` в CORS backend** — браузер перестанет слать OPTIONS перед каждым запросом, минус половина обращений.

## Что где лежит (для следующей сессии)
- **Слои** — `backend/app/spaces.py` (вся логика: автоправило, preview, снятие доступа) и `frontend/src/spaces.ts` (`useSpace`, `filterForSpace`). Правила слоёв менять там, а не в компонентах. Единственная точка применения на фронте — `store.ts`: экраны получают уже отфильтрованные списки, поэтому новый экран подхватит слои сам, если берёт данные из стора.
- **Перетаскивание** — `frontend/src/dnd.ts` (типы переноса, `insertBefore`, `moveTaskToProject`, …). Панель и карта проектов вызывают только эти функции.
- **Action Tracker** — `frontend/src/ActionTracker.tsx`; `buildGroups(store, filters)` покрыт тестами, ответственный берётся из `task.assignees`.
- **Корзина** — `backend/app/trash.py`. Ключ ко всему — `deleted_at`: одно действие пользователя = один timestamp.
- **Порядок** — `sort_order` у проектов и задач; ноль у всех = прежний порядок.
- **Тесты.** Бэкенд: `backend/tests/`, `python -m pytest tests -q`; отдельно `python test_mcp.py` и `python test_v06.py` (печатают `ALL OK`). Фронт: `frontend/src/__tests__/`, `npm test`; фикстуры стора — `fixtures.ts` (новое поле в `Store` добавлять и туда).
- **Стенд для скриншотов:** `cd backend && python _serve_ui.py 8765` (sqlite с демо-данными, теперь и со слоями, + `frontend/dist`), в выводе — JWT владельца; дальше Playwright.
- **Миграции на sqlite не прогоняются** (старые используют `now()`): проверять цепочку только на Postgres. В облачной среде поднимается локальный Postgres 16 под пользователем `postgres` в `/var/tmp`.

## Правила работы в папке владельца (Cowork)
- Файлы записывать через мост, но **git не запускать вообще** (даже `git status` оставляет `.git/index.lock`). Если появился — `Remove-Item .git\index.lock`.
- Тесты гонять на копии в `$HOME`, не в папке владельца. Фронт в Linux-среде: копия `frontend` без `node_modules` → `npm ci` → сборка.
- Связь с компьютером может пропасть посреди сессии: готовые файлы держать в `/mnt/user-data/outputs/` и отдавать архивом в чат.
- **Пуш в GitHub из облачной среды запрещён прокси** (`not in this session's authorized repository set`) — клонировать можно, пушить нельзя. Поэтому доставка — архивом.
- В облачной среде `vitest` запускать как `env -u TZ npx vitest run` (иначе падает тест `showDate (Н6)`: конфиг ставит `TZ` только если переменной нет, а в контейнере задана `Asia/Oral`).
