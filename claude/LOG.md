## 2026-09-07 · сессия 14 · Cowork (desktop + папка) — v1.1: «потянуть сверху вниз — обновить» на телефоне

**Повод** — владелец: «в мобильном приложении нужна функция обновления: обычно тянешь сверху вниз — сайт обновляется, а у нас такого нет».

**Разбор перед работой** — жеста нет по двум причинам: (1) PWA с экрана «Домой» открывается без браузерной оболочки, и системного «потянуть-обновить» там нет в принципе; (2) в самом приложении он отключён нашим же `body { overscroll-behavior-y: none }` (v0.11, чтобы экран не «пружинил»). Значит, жест нужен свой, и вешать его надо на реальный прокручиваемый контейнер — на телефоне это `.main`, а не `window`.

**Решения владельца (2026-09-07)** — при жесте **перечитывать данные на месте** (без перезагрузки страницы, как в Telegram/Linear); если уже скачана новая версия сайта — применить её заодно. Индикатор — в духе Huly/Linear: тонкое кольцо цвета акцента, без подписей.

**Сделано (только фронт, миграций и переменных нет)**
- `src/PullToRefresh.tsx` — хук `usePullToRefresh(ref, onRefresh, enabled)` и компонент `PullIndicator`. Жест начинается только при `scrollTop === 0` и движении пальца вниз ≥6px (тап не считается); натяжение с сопротивлением (`damp`), порог 64px, максимум 96px; слушатели **пассивные** (без `preventDefault`) — прокрутка не тормозится; во время обновления повторный жест игнорируется; ошибку показывает обычная плашка `store.error`, индикатор просто убирается. Фазы: `pulling → armed → refreshing → done (галочка 0.4 с) → idle`; `role="status"` с подписью для читалок экрана («Потяните…», «Отпустите…», «Обновляю…», «Обновлено»).
- `src/store.ts` — новая функция `refresh()`: то же, что `reload()`, но **без экрана «загрузка…»** — данные меняются на месте; `reload()` теперь = `loading` вокруг `refresh()`.
- `src/update.ts` — `updatePending()`: ждёт ли уже скачанная новая версия. В `App.tsx` жест: если новая версия есть и нет несохранённых форм (`hasDirtyForms`, правило В3) — `applyUpdate()`, иначе `store.refresh()`. `mainRef` на `<main>`, индикатор рендерится только на телефоне.
- `src/styles.css` (блок v0.11) — `.ptr*`: кольцо в диске 36px выезжает из-под верхнего края на величину натяжения, дорисовывается по мере натяжения (`--ptr-p`), при `armed` штрих толще, при `refreshing` крутится, при `done` — зелёная галочка; `prefers-reduced-motion` учитывается; `.shell.mobile .main { overscroll-behavior-y: contain }`. На компьютере ничего не меняется.
- Версия **1.1**: `main.py` → `1.1.0`, сайдбар → `v1.1`.
- **Проверка:** `npm test` → **72 passed** (новый `src/__tests__/pull.test.tsx`, 5 тестов: достаточное натяжение запускает обновление и показывает фазы; короткое — нет; из середины списка — нет; во время обновления второе не стартует; на компьютере слушателей нет); `npm run build` чисто. Playwright (iPhone 13, CDP touch-события, dist + подменённый API): кадры pulling → armed → refreshing → done → idle сняты и просмотрены. Тесты и сборка гонялись в среде Claude на копии (в папке владельца `node_modules` собраны под Windows — в Linux-VM не запускаются).
- Файлы записаны прямо в папку владельца (git не запускался). Во `frontend/node_modules/.cache/` остались два служебных файла сессии (`_ptr_patch.py`, `_ptr_front.tgz`) — они вне git, удалять не обязательно.

**Урок** — «нет системной функции» в PWA почти всегда значит «мы сами её выключили или оболочки нет»; проверять, где реальный скролл-контейнер, прежде чем вешать жест на `window`.

**Осталось** — владелец: `npm run build`, `npm test` (72), коммит/пуш; после деплоя на телефоне: потянуть список вниз на Карте/Задачах/Поручено → кольцо → данные обновились; открытая карточка задачи жест не ловит (это отдельный экран поверх). Идеи дальше: свайп между статусами, долгое нажатие вместо «⋯», push-уведомления PWA.
