# Адверсариальный UX-ревью фронтенда Planner (v0.7)

Дата: 2026-09-04. Область: `frontend/src/*.tsx|ts`, бэкенд-роутеры — только для сверки последствий.
Метод: чтение кода построчно; сборку (`npm run build`) не запускал (в контейнере нет `node_modules`), реальные клики в браузере не делал. Каждый пункт помечен: **проверено по коду** (поведение однозначно следует из кода) или **не проверено** (гипотеза, нужна проверка руками).

Легенда серьёзности:
- **Критично** — человек теряет данные одним привычным движением, и UI сам его к этому подводит.
- **Высоко** — потеря данных или ложное состояние в частом сценарии.
- **Средне** — потеря/ложь в редком сценарии или требует стечения обстоятельств.
- **Низко** — раздражает, путает, но данные целы.

### К1. «Без проекта»: правая кнопка открывает меню НАПРАВЛЕНИЯ, и «Удалить направление…» стоит там, где ждёшь «Удалить проект…»
**Файл:** `DirectionPage.tsx:63` (страница целиком: `onContextMenu={onDirectionMenu}`), `DirectionPage.tsx:108-124` (карточка `DropCard` «Без проекта» — без `onContextMenu`, без кнопки «⋯»), для сравнения `DirectionPage.tsx:157,161` (у `ProjectCard` есть и `stopPropagation`, и «⋯»). **Проверено по коду.**

**Шаги владельца:** Карта проектов → правая кнопка на карточке «Без проекта» (или на любом пустом месте страницы, на заголовке, на строке задачи внутри «Без проекта») → в меню видит красную строку «Удалить направление…» → кликает, думая, что убирает пустой блок → диалог с уже сфокусированной красной кнопкой → Enter/клик → **направление удалено вместе со всеми проектами**, задачи потеряли привязку.

**Исправление:** в `DropCard` «Без проекта» добавить `onContextMenu={(e) => { e.preventDefault(); e.stopPropagation(); }}` (или своё маленькое меню: «Открыть доску», «+ Задача без проекта»); снять `onContextMenu` с корня `DirectionPage` и оставить его только на шапке `.dir-head` (где написано имя направления) — правая кнопка на пустом месте страницы не должна открывать деструктивное меню. ### В2. Гонка автосохранения: набор текста во время запроса откатывается назад («буквы пропадают»)
**Файл:** `TaskPanel.tsx:28` (`if (!dirty) setDraft(toIn(task))`), `TaskPanel.tsx:45-46` (`store.patchTask(saved); setDirty(false)`). **Проверено по коду.**

## Проверяемые функции для юнит-тестов (vitest)

Ниже — чистые функции и небольшие компоненты, тесты на которые дёшевы и ловят регрессии из этого отчёта.

### `api.ts`
- `isOverdue(iso)`: `null/undefined/""` → `false`; прошедшая ISO с `Z` → `true`; будущая → `false`; строка `"2026-09-04T23:59:59"` (без Z) сравнивается как локальное время — тест с `vi.setSystemTime` на границе 23:59:59/00:00:00.
- `showDate(iso)`: `"2026-09-04"` должна давать «04 сент.» **в любом поясе** (сейчас упадёт при `TZ=America/New_York` — Н6); `null` → `""`.
- `toDateInput`/`toDateTimeInput`/`fromDateTimeInput`: round-trip `fromDateTimeInput(toDateTimeInput(iso))` возвращает тот же момент времени; `fromDateTimeInput("")` → `null`; `toDateTimeInput(null)` → `""`.
- `canEdit(access)`: `undefined/null/"owner"/"edit"` → `true`; `"view"/"via"/"assignee"` → `false`. `isShared`: только `edit|view`.
- `dirColor`, `projColor`: свой цвет приоритетнее палитры; `projColor` без направления в списке → `"var(--line-strong)"`; отрицательных/больших id нет, но `id % 8` для `id=0` → первый цвет.
- `newNodeId()`: длина 1–8 символов `[a-z0-9]`, 10 000 вызовов без коллизий (проверка гипотезы Н-уровня о дубликатах id чеклиста).

### `Overview.tsx` — `buildReport(direction, tasks, now)`
- Нет задач → `score=45`, `reasons=["нет ни одной задачи"]`, `level=ok` (45 → «Норма»? граница `score < 45 ? ok : fading` — 45 даёт **fading**; зафиксировать ожидание).
- Пауза → `score ≤ 15`, `reasons=["на паузе"]` независимо от просрочек.
- Просрочка считается по `${deadline}T23:59:59` локально: задача с дедлайном «сегодня» **не** просрочена в 23:00, просрочена в 00:00 следующего дня (`vi.setSystemTime`).
- `idleDays`: `updated_at` минуту назад → 0; 13 дней → без причины; 14 → «нет движения 14 дн.»; 7 → «тихо уже 7 дн.»; `updated_at` в будущем (расхождение часов) → не должно давать отрицательный `idleDays` (сейчас даст `-1`; решить — `Math.max(0, …)`).
- Верхние границы: 5 просрочек → +30 (не +75); 3 пропущенные проверки → +20; итог ≤ 100 и целое.
- Фильтрация по направлению: задачи других направлений не учитываются; задача в двух направлениях учитывается в обоих.
- `count()`/доли для `stack`: `total=0` → все `pct=0` (нет `NaN`).

### `Checklist.tsx` — `checklistProgress(items)`
- `undefined/null/[]` → `{total:0, done:0, pct:0}`; `[done,done,open]` → `{3,2,67}` (округление); все выполнены → `pct=100`.
- Компонент (react-testing-library): Enter в поле добавления → `onChange` с новым пунктом и очищенным полем; пустой Enter → `onChange` не вызывается; blur пустого существующего пункта → пункт удалён (зафиксировать текущее поведение, а после исправления С3 — что **не** удалён); `readOnly` + пусто → `null`.

### `confirm.tsx` — `ConfirmProvider`/`useConfirm`
- Открытие: `role="alertdialog"`, заголовок по умолчанию для `danger` — «Подтвердите удаление», кнопка — `okLabel ?? "Удалить"`.
- Какая кнопка в фокусе после открытия (`document.activeElement`) — сейчас «Удалить»; после исправления К2 — «Отмена».
- Escape → resolve(false); клик по фону → `false`; клик внутри модалки по тексту → диалог не закрывается.
- Enter при открытом диалоге **не** должен долетать до других `window`-слушателей (тест с фейковым слушателем — сейчас долетает, С4/С9).
- Повторный вызов `ask()` во время открытого диалога — что происходит с первым промисом (сейчас он никогда не резолвится: `setState` перезаписывает `resolve`) — зафиксировать ожидаемое (`false`).

### `DirectionPage.tsx` / `TaskPanel.tsx` — `toIn(task, projectId)`
- `deadline: ""` → `null`; `checklist: undefined` → `[]`; `project_id` подставляется из аргумента; `direction_ids`/`tool_ids` — по id, без дублей.
- `plural(n, …)`: 1/21/101 → «проект», 2–4/22 → «проекта», 5–20/11–14/25 → «проектов», 0 → «проектов».

### `MindMapEditor.tsx` (экспортировать для тестов: `wrap`, `measure`, `layout`, `mapTree`, `findParent`, `findNode`, `countAll`)
- `wrap("", n)` → `[" "]`; длинное слово длиннее `maxChars` не теряется; `wrap` не даёт пустых строк.
- `layout(root)` с `collapsed` корнем → только корень; дети делятся на две стороны по высоте; у каждого не-корня есть `parent`.
- `findParent(root, root.id)` → `null`; `countAll(leaf)` → 1.
- `mapTree` иммутабельна: исходное дерево не меняется (`toStrictEqual` до/после).

### `store.ts` (через `renderHook` с моком `api`)
- Видимость задач: чужая задача с `access:"assignee"` попадает в `inbox`, а на доску — только если её направление/проект открыты мне; задача без `owner` видна.
