# MCP-коннектор CIS Planner для Claude

Планнером можно управлять разговором с Claude — в claude.ai, в мобильном приложении (в том числе
голосом) и в Claude Desktop: «запиши задачу…», «поручи Ержану…», «напомни в пятницу…»,
«что у меня по снабжению», «как справляется Айдос», «кто не успевает».

## Как подключить (себе или коллеге)

1. В Claude: **Settings → Connectors → Add custom connector**.
2. URL: `https://backend-production-830f1.up.railway.app/mcp`. Нажать **Add**.
3. Нажать **Connect** — откроется вход через Microsoft (рабочая учётка @cis.kz), затем страница
   планнера «Разрешить». После этого Claude работает от вашего имени: видит ваши направления и задачи
   плюс то, что поручено вам.
4. В мобильном приложении коннектор включается в настройках чата (иконка инструментов) — после этого
   голосовые команды тоже идут в планнер.

Отзыв доступа — удалить коннектор в Claude (Settings → Connectors → Remove).

## Что умеет Claude через коннектор

**Сводки и отчёты**

| Инструмент | Что делает |
|---|---|
| `get_overview` | «что сегодня»: шкала внимания по направлениям, дедлайны сегодня, просрочки, проверки, кого спросить, что поручено мне |
| `list_directions` / `get_direction_summary` | направления со статистикой; подробная сводка по одному направлению (задачи по статусам, люди, тулы) |
| `list_tasks` / `get_task` | поиск задач (направление, статус, человек, просроченные, ближайшие N дней, текст, «мне поручено»); карточка задачи |
| `list_people` / `get_person_report` | справочник людей; отчёт по человеку: выполнено/открыто, доля выполненных, доля вовремя, средний срок, просрочки, пропущенные проверки, отчёты |
| `get_team_report` | все люди сразу, отсортированы по проблемности («кто не справляется») |

**Запись**

| Инструмент | Что делает |
|---|---|
| `create_direction` / `update_direction` | создать направление; изменить название, цель, описание, цвет, статус (пауза / архив) |
| `create_task` | создать задачу — сразу с направлениями, дедлайном, приоритетом, исполнителями, датой проверки и напоминанием |
| `update_task` / `set_task_status` / `add_task_note` | изменить задачу; сменить статус (доступно и исполнителю); дописать заметку с отметкой времени |
| `delegate_task` / `update_delegation` | поручить задачу людям; закрыть/вернуть поручение, записать отчёт исполнителя, перенести проверку |
| `add_reminder` | напоминание по задаче: Telegram / почта / событие в календаре Outlook; мне / исполнителям / обоим |
| `create_person` / `add_tool` | добавить человека в справочник; добавить тул |

**Удаления нет** — вместо него статус «выполнено», направление на паузу или в архив.

Права те же, что в интерфейсе: свои задачи — полностью; порученные мне — статус и отчёт.

## Памятка: чтобы Claude сразу понимал «запиши» и «поручи»

Сервер при подключении сам передаёт Claude правило: слова «запиши», «добавь задачу», «поручи»,
«напомни», «поставь срок», «отметь выполненным», «сводка», «как дела у …» — это команды планнеру.
Для надёжности (особенно в голосовом режиме) добавьте в Claude → Settings → Profile → *Personal preferences*:

> У меня подключён коннектор CIS Planner — мой рабочий планнер (направления → задачи → поручения людям → сроки и напоминания).
> Когда я говорю «запиши», «добавь задачу», «поручи», «напомни», «поставь срок», «отметь выполненным», «что у меня»,
> «сводка», «как дела у …», «что по …» — сразу используй инструменты CIS Planner, не спрашивай, куда записать.
> Даты вроде «завтра», «в пятницу» переводи в конкретные сам. После записи коротко подтверждай, что создано.

## Технически / администратору

- Эндпоинты бэкенда: `POST /mcp` (MCP Streamable HTTP, stateless JSON), OAuth 2.0: `/oauth/register` (DCR),
  `/oauth/authorize` → вход через Microsoft (тот же `/api/auth/callback`, state `mcp:<key>`) → `/oauth/consent`,
  `/oauth/token`; метаданные `/.well-known/oauth-authorization-server` и `/.well-known/oauth-protected-resource`.
- Код: `backend/app/routers/mcp_oauth.py` (OAuth), `backend/app/routers/mcp.py` (JSON-RPC), `backend/app/mcp_tools.py`
  (инструменты и инструкции для Claude). Миграция `f1a5b6c7d8e9` (таблицы `mcp_clients`, `mcp_pending_auth`,
  `mcp_auth_codes`, `mcp_tokens`).
- Клиенты публичные, PKCE S256 обязателен; access-токен 8 часов, refresh 30 дней с ротацией; в базе — только SHA-256 хеши.
- Служебный `API_TOKEN` тоже принимается как Bearer на `/mcp` (от имени владельца) — для отладки и Claude Code.
- Если в Entra не заданы `MS_*`, страница согласия просит служебный токен (локальная разработка).
- Переменная `PUBLIC_URL` (публичный адрес бэкенда) — необязательна: без неё адреса строятся из `X-Forwarded-*`.
- Настроек в Entra не требуется: используется существующий redirect `/api/auth/callback`.
- Вызовы инструментов пишутся в лог бэкенда (`mcp tools/call <имя> by <почта>`), выдача доступа — в `activity_log`
  (`McpClient/authorized`). Записи, сделанные через Claude, помечены в `activity_log` `{"via": "mcp"}`.

## v0.6 — проекты и совместный доступ
Новые инструменты: `list_projects`, `create_project`, `update_project` (проекты внутри направлений: «заведи проект Договор бурение в Эмбе»), `share_access` / `revoke_access` / `list_shares` («поделись Эмбой с n.abilkhanov@cis.kz на редактирование», «что мне открыли»). `create_task` и `update_task` принимают `project`, `list_tasks` фильтрует по `project`. Через коннектор видно и то, что открыли вам коллеги (с пометкой `shared_by`/`access`).

## v0.6.1 — понятные ошибки инструментов
- Любая ошибка инструмента возвращается Claude как `isError` с JSON `{"error": "что не так", "hint": "что сделать"}`. Подсказки: уточнить название из списка кандидатов, создать недостающий проект/направление/человека (`create_project`, `create_direction`, `create_person` или флаги `create_*_if_missing`), убрать поле `project`. Инструкции сервера велят Claude следовать `hint`, а не повторять вызов или объявлять сбой.
- В `create_task` добавлен флаг `create_project_if_missing` (нужно ровно одно направление в `directions`). В описаниях инструментов явно сказано: направление/проект/человек должны уже существовать.
- Списковые аргументы (`directions`, `assign_to`, `people`, `channels`…) принимают и одну строку вместо массива; `arguments` JSON-строкой тоже разбираются; каналы `calendar`/`mail`/`почта` нормализуются.
- В логах бэкенда (Railway) для каждой ошибки — `WARNING mcp: <инструмент> by <почта>: <текст ошибки> | args={…}`; для неожиданных исключений — полный traceback. Искать: фильтр `WARNING mcp` или `-> error`.

## v0.7 — чеклист в задаче
- У задачи есть чеклист (`Task.checklist`, JSON `[{"id","text","done"}]`). В `get_task` — список пунктов, в `list_tasks` — прогресс `2/5`.
- Инструменты: `add_checklist_items(task, items[])` — добавить пункты («разбей на шаги», «добавь пункты»); `check_item(task, item, done=true)` — отметить/снять (пункт ищется по тексту или его части; доступно владельцу, редактору и исполнителю).
