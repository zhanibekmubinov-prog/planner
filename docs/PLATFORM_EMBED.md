# Планнер вкладкой внутри платформы CIS (v1.5)

Платформа CIS открывает планнер разделом «Планнер» — в рамке (iframe) на своей странице.
Вход внутри рамки отдаёт сама платформа: она уже опознала сотрудника через Microsoft (тот же
Entra, что и у планнера) и выдаёт одноразовый билет, который планнер меняет на свою сессию.

## Почему так, а не «просто iframe»

- `login.microsoftonline.com` отдаёт `X-Frame-Options: DENY` — форма входа Microsoft внутри
  рамки не откроется.
- Браузер делит `localStorage` по верхнему сайту: сессия, полученная при прямом заходе на
  планнер, внутри рамки платформы не видна.

Поэтому голая рамка показала бы экран «Войти», по которому нельзя войти.

## Как это работает

1. Сотрудник открывает в платформе раздел «Планнер».
2. Платформа выписывает билет — JWT, подписанный HS256 общим секретом:
   `iss=cis-platform`, `aud=cis-planner`, `email`, `name`, `iat`, `exp` (≈60 с), `jti`.
3. Рамка грузит `https://<бэкенд планнера>/api/auth/platform?t=<билет>`.
4. Планнер проверяет подпись, срок, потолок возраста (`PLATFORM_TICKET_MAX_AGE_SEC`, 120 с) и
   одноразовость `jti`; заводит пользователя по почте (и запись в «Людях», чтобы ему можно было
   поручать задачи) и уводит на `<фронт>/?embed=1#token=<сессия>` — так же, как после возврата
   от Microsoft.
5. Фронт забирает токен из фрагмента, а по `?embed=1` понимает, что он в рамке: не рисует свой
   логотип и не предлагает кнопку Microsoft.

## Переменные окружения

| Сервис | Переменная | Значение |
|---|---|---|
| планнер `backend` | `PLATFORM_SSO_SECRET` | случайная строка ≥16 символов; **та же** у платформы. Пусто = вход из платформы выключен (503) |
| планнер `backend` | `PLATFORM_TICKET_MAX_AGE_SEC` | необязательно, по умолчанию 120 |
| планнер `frontend` | `PLATFORM_ORIGIN` | адрес платформы, напр. `https://platform.cis.kz`; несколько — через запятую |
| платформа | `PLANNER_SSO_SECRET`, адрес планнера | см. заметки платформы |

Секрет генерируется так:

```
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

`PLATFORM_ORIGIN` попадает в заголовок `Content-Security-Policy: frame-ancestors 'self' <адрес>`
(файл `dist/serve.json` пишется при старте, `scripts/serve-headers.mjs`). Пока переменная пуста,
планнер не встроится никуда — это и защита от кликджекинга, и первая причина «раздел пустой».

## Что проверить после деплоя

1. Раздел «Планнер» в платформе открывается и показывает доску — на ноутбуке и на телефоне.
2. DevTools → Network: запрос `/api/auth/platform` отвечает 307, в консоли нет `Refused to frame`.
3. Повторное открытие раздела не спрашивает вход заново.
4. Скопированная ссылка `/api/auth/platform?t=…`, открытая второй раз, даёт 401 «билет уже
   использован» — билет одноразовый.

## Известные ограничения

- Внутри рамки нет установки PWA и push-уведомлений: на телефоне планнер ставится на домашний
  экран по своему прямому адресу.
- Если сессия не открылась (ключ протух, нажали «назад»), внутри рамки показывается объяснение и
  ссылка «Открыть планнер в отдельной вкладке» — кнопки Microsoft там нет намеренно.
