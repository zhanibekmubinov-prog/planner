# Бот планнера: подключение Telegram в один клик (v0.9)

Раньше сотрудник должен был сам искать свой chat id (через @userinfobot) и вписывать его в профиль.
Теперь бот `@cisplannerbot` умеет отвечать сам:

| Команда | Что делает |
|---|---|
| `/start <код>` | Привязывает чат к учётной записи. Код приходит из ссылки, которую даёт кнопка «Подключить Telegram» в профиле планнера |
| `/start` | Показывает chat id и объясняет, что делать |
| `/id` (`/myid`, `/chatid`) | Показывает chat id и к кому чат привязан |
| `/stop` | Отключает напоминания в этот чат |
| `/help` | Короткая справка |
| любой другой текст | chat id + справка |

Сотруднику копировать ничего не нужно: профиль → **«Подключить Telegram»** → открывается бот → **«Запустить»** → бот отвечает «Готово, Имя!». Кнопка «Проверить» в профиле подтягивает результат.

## Как это устроено

- Вебхук: `POST /api/telegram/webhook`. Проверяется заголовок `X-Telegram-Bot-Api-Secret-Token` — он должен совпасть с `TELEGRAM_WEBHOOK_SECRET`. Не совпал → 403; секрет не задан → 503.
- Код привязки (`app/telegram_link.py`) — это `<id пользователя>-<HMAC на SESSION_SECRET>`, **в базе не хранится** (миграция не нужна). Живёт сутки, принимаются текущие и предыдущие сутки.
- Один чат = один человек: при привязке чат снимается у всех остальных пользователей и записей «Люди».
- Привязка пишется и в `User.telegram_chat_id`, и в связанную запись `Person` — как это делает сохранение профиля.
- Ответы бота уходят через `sendMessage`. Если `TELEGRAM_BOT_TOKEN` пуст (локально, в тестах) — бот молчит, ошибок нет.
- Любое исключение внутри обработчика логируется, но вебхук всегда отвечает `{"ok": true}` — иначе Telegram будет повторять апдейт по кругу.

## Настройка (один раз, владелец)

1. В Railway у сервиса `backend` добавить переменные:

   ```
   TELEGRAM_BOT_USERNAME=cisplannerbot
   TELEGRAM_WEBHOOK_SECRET=<случайная строка, 32+ символа>
   ```

   Секрет можно получить так: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

2. Дождаться перезапуска бэкенда и один раз открыть в браузере (подставив токен бота и тот же секрет):

   ```
   https://api.telegram.org/bot<ТОКЕН_БОТА>/setWebhook?url=https://backend-production-830f1.up.railway.app/api/telegram/webhook&secret_token=<СЕКРЕТ>
   ```

   Ответ должен быть `{"ok":true,"result":true,"description":"Webhook was set"}`.

3. Проверка: написать боту `/id` — он должен ответить вашим chat id.

Полезное:

- посмотреть состояние вебхука — `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`
- снять вебхук — `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`
- в BotFather у бота стоит включить пункт меню команд (`/setcommands`):

  ```
  id - показать мой chat id
  stop - не присылать напоминания
  help - справка
  ```

## Если бот молчит

1. `getWebhookInfo` — есть ли `last_error_message`. `Wrong response from the webhook: 403` значит секрет в Railway и в setWebhook разные.
2. Логи Railway у `backend`: строка `telegram: chat <id> привязан к <почта>` — привязка прошла; `WARNING telegram` — ошибка отправки.
3. Пользователь не нажал «Запустить»: пока человек не начал диалог, бот по правилам Telegram писать ему не может.
